# P04 — Provider secrets out of the WebView (H-01)

STATUS: done
BRANCH: fix/p04-provider-secrets
FILE: src/lib/stores/providers.svelte.ts (only)

## What was wrong
The store already stripped the legacy `apiKey` from persisted JSON, but the
new/update flows called the one-shot IPC `set_provider_api_key` inside a
try/catch that swallowed the error, then set `hasApiKey: true` unconditionally.
Result: a provider looked configured when no credential was actually stored, and
key rotations reported success with no effect.

## What changed
- `setProviderApiKey` no longer swallows IPC failures. In the Tauri runtime it
  awaits `invoke("set_provider_api_key", { args: { provider_id, api_key } })`
  with NO try/catch, so a rejection propagates to the caller. In browser
  fallback (`!api.isTauriRuntime()`) the key is dropped (no keychain) and it
  resolves — dev-only convenience.
- New-provider path: creates the backend row, then stores the key BEFORE
  publishing `hasApiKey`. On key-storage failure it rolls back the just-created
  provider via `api.removeProvider(info.id)` and rethrows, so no keyless
  provider is left looking configured. `hasApiKey` is only `true` after the IPC
  durably resolves.
- Update/rotate path: metadata update is reflected first with the provider's
  PREVIOUS `hasApiKey`; the new key is rotated separately. `hasApiKey` flips to
  `true` only after the rotation IPC resolves. If it rejects, the error surfaces
  and the provider keeps its prior (truthful) key state.
- Plaintext key input (`input.apiKey`) is cleared to `""` immediately after a
  successful hand-off in both paths. The store never holds the plaintext.
- Startup migration: on module load, if `lh.providers.v1` exists in
  localStorage, `persistProviders()` immediately overwrites it with the
  already-stripped in-memory providers, so a plaintext key from a pre-fix build
  cannot linger on disk until the first hydrate. Unparseable blob => providers
  is [] => cleared (fail closed).

## Invariants held
- No code path writes an API key into localStorage (persistProviders whitelists
  fields; migrate strips `apiKey`; startup rewrite scrubs legacy payloads).
- `hasApiKey: true` only after the durable IPC succeeds; failures are truthful.
- Fail-closed: rollback on new-provider key failure; no phantom rotation success.
