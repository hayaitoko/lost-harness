**Status**: DONE, implemented directly on `review-fixes/integration`.
**Codex verdict on the original attempt**: REVISE — "Proposed CI is permanently

## Why this was not done in wt-P21

The packet's own branch is based on `eb17b94`. An adversarial review of that branch
refuted it with 15 findings, and roughly half were artifacts of the stale base: it could
not see P17's macOS-arm64-only matrix or P20's `audit.toml`, so it rewrote exactly the
lines those merged packets own, and its gates were measured against a tree that no longer
exists. CI gates can only be judged against the tree they will actually run on, so this
work was done on the integration branch after all 22 other packets merged.

The refuted branch also contained a **fabricated validation transcript** — a Python REPL
session showing `import yaml; yaml.safe_load(...)` → `YAML OK`. PyYAML is not installed in
any python3 on this machine, so that session never ran. None of it was carried over.

## The find: P20's audit gate was silently dead

`.github/workflows/build.yml` carried:

```yaml
- name: cargo audit (gate — exceptions in src-tauri/.cargo/audit.toml)
  if: matrix.os == 'ubuntu-latest'
```

That condition dates from the pre-P17 three-OS matrix. **P17 removed the matrix**, so
`matrix.os` became an undefined context, the expression evaluated false, and the step
never ran. P20 spent an entire packet turning `cargo audit` from advisory noise into a
hard gate with a codified exception file — and the gate was disabled by a leftover
condition from a different packet. Exactly the merge collision P20's reviewer predicted.

Fixed by deleting the condition. The audit is lockfile-only, so the single macOS job is
the right place for it.
