## Summary

The vendored `llama-server` runtime ships only as `macos-arm64`, yet the
packaging config requested all targets (`"targets": "all"`) and the CI
toolchain installed both `aarch64-apple-darwin` and `x86_64-apple-darwin`
without building either explicitly. This created a misleading cross-arch
signal: the code and resources were arm64-only, but the packaging and CI
matrix suggested broader support.

## H-09 fix: arm64-only enforcement

- **tauri.conf.json:** `bundle.targets` changed from `"all"` (which requests
  DMG, MSI, AppImage, deb, etc.) to `["dmg"]` — macOS-only DMG.
- **lib.rs:** A `#[cfg(not(target_arch = "aarch64"))]` `compile_error!` fires
  when `feature = "local-runner"` is enabled on a non-arm64 target, with a
  clear message directing the developer to set `--target aarch64-apple-darwin`
  or remove the feature.
- **build.yml:** Toolchain target installation narrowed to
  `aarch64-apple-darwin` only. All cargo commands (build, clippy, test) now
  specify `--target aarch64-apple-darwin` explicitly for the macOS runner.

## H-10 fix: honest minimum OS documentation

- **README.md:** Support matrix table documents:
  - Architecture: Apple Silicon (arm64) only
  - Minimum OS: macOS 15 (Sequoia) or later
  - The vendored `llama-server` binary's `LC_BUILD_VERSION minos 26.0` as the
    basis for the minimum OS requirement
  - A note that if deployment on an older macOS is needed, the vendored
    llama.cpp must be rebuilt against the appropriate SDK

> **Note on build validation:** The test host is x86_64 (Rosetta). With default
> features (`local-runner` enabled), `cargo build` correctly fails with the
> new `compile_error!` — this is the intended enforcement. The
> `--no-default-features` build succeeds, confirming the rest of the crate
> is unaffected. On arm64 CI runners (`macos-latest`), `cargo build` with
> default features passes because `target_arch = "aarch64"` is true.

## Needs human decision

1. **Rebuild vendored llama.cpp + dylibs against the documented minimum
   deployment target, then validate the signed app on the oldest supported
   OS.** The current vendored `llama-server` binary (`vendor/llama-cpp/macos-arm64/`)
   has `LC_BUILD_VERSION minos 26.0` (darwin 26 / LLVM-based versioning),
   which corresponds to a newer minimum OS than the current macOS 15 baseline.
   A manual rebuild of llama.cpp targeting the correct macOS SDK is needed to
   produce a runtime that matches the documented macOS 15 minimum.

   Steps:
   - Clone [llama.cpp](https://github.com/ggml-org/llama.cpp)
   - Build with `-DCMAKE_OSX_DEPLOYMENT_TARGET=15.0` (or the target OS)
   - Replace the `llama-server` binary and all `.dylib` files in
     `vendor/llama-cpp/macos-arm64/`
   - Update `VERSION` and `MANIFEST.sha256` in that directory
   - Validate the resulting `.app` bundle on the oldest supported macOS
     version

2. **Verify the DMG build works end-to-end.** The `bundle.targets` change
   from `"all"` to `["dmg"]` constrains Tauri to macOS-only packaging. A
   `npm run tauri build` should be run on an arm64 macOS host to confirm the
   DMG is produced correctly and the packaged app resolves the vendored
   runtime.
