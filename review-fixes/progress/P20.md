### Dependency chain analysis

**GTK3 cluster (Linux-only, 11 crates):**
```
lost-harness-product → tauri 2.11.5 → tauri-runtime-wry 2.11.4 → {
    tao 0.35.3 → gtk 0.18.2 → glib 0.18.5
    muda 0.19.3 → gtk 0.18.2 → glib 0.18.5
    wry 0.55.1 → webkit2gtk 2.0.2 → gtk 0.18.2 → glib 0.18.5
}
```
- **Cannot upgrade.** webkit2gtk is a GTK3-based C library; the Rust bindings remain at gtk-rs 0.18.x. GTK3 bindings are unmaintained (upstream moved to gtk4-rs), but webkit2gtk has no GTK4 port. Affects Linux builds only.
- glib 0.18.5 → 0.20 is a breaking change incompatible with gtk-rs 0.18.x.
- `cargo update -p muda -p tao -p wry -p webkit2gtk` confirms all at latest compatible versions.

**tokenizers cluster (onnx-classifier feature only, 2 crates):**
```
lost-harness-product → tokenizers 0.20.4 → {
    indicatif → number_prefix 0.4.0 (unmaintained)
    macro_rules_attribute → paste 1.0.15 (unmaintained)
}
```
- `number_prefix` 0.4.0 is the latest version (no replacement available).
- `paste` 1.0.15 is the latest version (no replacement; alternatives: pastey, with_builtin_macros).
- Tokenizers 0.20.4 is the latest compatible version; upgrading requires breaking change.

**proc-macro-error (Linux-only):**
```
glib-macros 0.18.5 → proc-macro-error 1.0.4 (unmaintained)
```
- Tied to the GTK3 cluster. Can't fix without upgrading the GTK stack.

**unic-* cluster (cross-platform, 5 crates):**
```
lost-harness-product → tauri 2.11.5 → tauri-utils 2.9.3 → urlpattern 0.3.0 → {
    unic-ucd-ident → unic-common, unic-char-property, unic-char-range, unic-ucd-version
}
```
- `urlpattern` 0.3.0 is the version pinned by tauri-utils 2.9.3. Upstream urlpattern 0.6.0 drops the unic dependencies, but tauri-utils pins to 0.3.0 — a breaking change.
