## Summary

### L-06 — Module doc rewrite
Rewrote the module-level doc comment to accurately describe all six tools, their risk classes (Safe vs Write), the read-before-write guard, and the TOCTOU mitigations. The old doc claimed "read-only" and "no write/delete" — now it's accurate.

### M-03 — Profile name fail-closed
- `canonical_profile_name()`: validates against the exact same rules as `storage::validate_profile_name` (ASCII alphanumeric, `_`, `-`, ≤64 chars, rejects `..`/leading `.`), normalizes to lowercase
- `profile_workspace_path()`: calls `canonical_profile_name` internally; invalid/empty names return `base/__invalid_profile__` (never returns shared base)
- `ensure_valid_profile()`: early-exit validation for tool `run` methods

### M-04 — TOCTOU mitigations
- `fd_realpath()`: gets real path from an open fd via `fcntl(F_GETPATH)` (macOS)
- `open_verified()`: opens with `O_NOFOLLOW`, verifies fd real path is within workspace root
- `open_verified_write()`: same for write opens
- `resolve_within` and `resolve_within_new` unchanged (sync functions kept for `migrate_legacy_workspace` and `canonicalize_best_effort` callers)

### M-21 — Blocking I/O off async runtime
- `resolve_within_async` / `resolve_within_new_async`: wrap sync canonicalize in `spawn_blocking`
- `osascript()` in `macos/mod.rs`: wrapped in `tokio::task::block_in_place` so the subprocess call doesn't starve a tokio worker thread
