# P07 — Web-fetch SSRF connect-time pinning (H-03)

Status: DONE

## Finding
`fetch_url`'s `ssrf_check()` resolved and classified a host's IPs, but reqwest
re-resolved DNS at `.send()`. A DNS-rebinding name could return a public IP to
the check and a private/metadata IP to the actual connection (TOCTOU), defeating
the SSRF guard. The residual was documented but not closed.

## Change (src-tauri/src/tools/fetch.rs — only file touched)
- `ssrf_check()` now returns the vetted `Vec<SocketAddr>` it approved instead of
  `()` — IP literals return the single classified addr; hostnames return every
  resolved-and-vetted addr; fail-closed on unresolvable / any non-public IP.
- `fetch_readable()` builds a fresh `reqwest::Client` per hop pinned with
  `.resolve_to_addrs(hostname, &vetted)`, so reqwest never runs its own DNS — it
  connects ONLY to the addresses ssrf_check approved. The original hostname is
  kept in the request URL for correct TLS/SNI validation.
- Automatic redirects stay disabled (`redirect::Policy::none()`); each redirect
  hop re-runs `ssrf_check` AND re-pins the new vetted addr before connecting.
- Fail-closed posture preserved throughout.

## Tests added (all pass)
- `resolve_to_addrs_pins_connection_and_bypasses_dns` — proves a pinned client
  connects to the vetted addr and never re-resolves DNS at send time (the rebind
  is unreachable because the second lookup never happens).
- `ssrf_check_returns_vetted_addr_for_public_ip_literal` — public literal → vetted.
- `ssrf_check_refuses_private_ip_literal_and_returns_addr` — private literals
  refused; public non-default port preserved in the vetted addr.
- Existing `run_refuses_non_http_schemes_and_private_hosts_without_network`
  continues to cover private-address / bad-scheme refusal.
