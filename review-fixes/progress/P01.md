The `check_detailed` method now returns `Some(classification)` for Public (was `None`).

## Follow-ups / risks
1. The second `PrivacyGate::new(classifier)` at lib.rs:1060 (tool hook chain) does NOT receive the degraded flag — that call is in `build_dispatcher` outside the classifier-load region (cannot edit per task scope). The hook-chain gate governs tool-call privacy, not message-level egress, but should ideally also be degraded for consistency.
2. The `tauri.conf.json` classifier-resource entry (`"vendor/classifier": "models/classifier"`) cannot be added until the ONNX model files are placed at `vendor/classifier/` in the build tree. Currently they install out-of-band via pf-bundle. Reverting this entry was necessary to unblock `cargo build`.
3. The `has_sensitive` check in Public detection relies on `classification.spans` having `RuleCategory` entries. `HeuristicClassifier` has empty `spans` (the older classifier format), so it never triggers the high-confidence block. `RulesClassifier` and `EnsembleClassifier` produce categorized spans as expected. If `HeuristicClassifier` is the active classifier, the H-12 confirmation requirement de-facto only surfaces the classification without blocking.
4. The `log_decision` method may need a `ConfirmRequired` variant if the frontend needs to distinguish a hard block from a confirmation-needed block.
