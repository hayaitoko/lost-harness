### Summary

1. **Label rename `Trusted` → `Curated`** (`hf_search.rs:42,`78,`201,`548):
   - `TRUSTED_PUBLISHERS` → `CURATED_PUBLISHERS`
   - `Provenance::Trusted` → `Provenance::Curated`
   - Updated all module docs to explain that namespace curation ≠ cryptographic trust.
     Documented the three-tier hierarchy:
     | Manifest? | Allowlisted? | Label | Trust root |
     |---|---|---|---|
     | Yes | Yes/No | `Curated` | Signed manifest |
     | No  | Yes | `Curated` (degraded) | Live API |
     | No  | No  | `Community` | Live API + consent |

2. **Immutable revision pinning** (`hf_search.rs:378`):
   - `resolve_url()` now takes `revision` parameter instead of hardcoding `"main"`.
   - `parse_tree()` accepts `revision` and passes it through to resolve URLs.
   - `list_quants()` takes `revision` — tree endpoint uses `{revision}` not `main`.
   - Manifest-curated models pin an immutable commit SHA; others use `"main"`.

3. **Signed manifest verification** (`hf_search.rs:220-345`, new):
   - `ManifestEntry` struct: `revision` + `files: BTreeMap<String, String>`.
   - `ModelManifest` struct: `version`, `signed_at`, `signature` (Ed25519 hex),
     `models: BTreeMap<String, ManifestEntry>`.
   - `ModelManifest::load()`: reads from file path, returns `Ok(None)` on NotFound.
   - `ModelManifest::verify_signature()`: decodes base64 public key, hex signature,
     verifies Ed25519 signature over canonical JSON of `models`.
   - `MANIFEST_PUBLIC_KEY_B64`: placeholder constant with generation instructions.
   - `MANIFEST_FILENAME`: `"model-manifest.json"` relative to storage base.
   - `load_manifest()`: public API taking a `storage_base` path.

4. **Manifest-driven `model_detail()`** (`hf_search.rs:724-773`):
   - Loads manifest on each call (NotFound → degraded curation, no error).
   - When manifest entry exists: uses pinned revision + `Provenance::Curated`
     (regardless of publisher allowlist).
   - Overrides each file's SHA-256 with manifest-sourced value when available.
   - Falls back to `"main"` + publisher allowlist when no manifest entry.

5. **Community-model consent preserved** (unchanged in `src-tauri/src/ipc/mod.rs:1459`):
   - The `acknowledge_community` guard for `Provenance::Community` still works.

### Follow-ups

1. **Replace `MANIFEST_PUBLIC_KEY_B64`** with the real application Ed25519 public key
   before production. The placeholder will fail signature verification. See the doc
   comment on the constant for generation steps.

2. **The manifest path** in `model_detail()` is hardcoded as `"model_manifest.json"`
   (relative to cwd). This should use `load_manifest(storage_base)` with the app's
   configured storage path once that's available in the library code.

3. **A human must generate and sign the manifest file.** The format is:
   ```json
   {
     "version": 1,
     "signed_at": "2026-07-28T00:00:00Z",
     "signature": "<ed25519-hex-signature>",
     "models": {
       "Qwen/Qwen3-0.6B-GGUF": {
         "revision": "<full-40-char-commit-sha>",
         "files": {
           "Qwen3-0.6B-Q8_0.gguf": "<64-char-sha256>",
           "Qwen3-0.6B-Q4_K_M.gguf": "<64-char-sha256>"
         }
       }
     }
   }
   ```
   The signature covers the canonical JSON of the `models` object only (BTreeMap
   ensures deterministic ordering). Sign with:
   ```
   echo -n '<canonical-models-json>' | openssl pkeyutl -sign -inkey manifest_private.pem -rawin | xxd -p | tr -d '\n'
   ```

4. **Publisher allowlist entries** that lack a manifest entry produce degraded
   curation — the label says "Curated" but the trust root is still the live API.
   The long-term goal is to have every curated publisher's models in the manifest.

### Needs human decision

- The `model_detail()` manifest path (`"model_manifest.json"`) should be
  configurable through app settings once the storage layer is available in lib code.
- The `MANIFEST_PUBLIC_KEY_B64` placeholder must be replaced with a real key.
- Decide which concrete models + revisions go into the first signed manifest.
