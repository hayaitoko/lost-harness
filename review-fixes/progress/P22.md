## What was wrong (and is now fixed)

The first pass at `src/tests/approval.test.ts` was **tautological**. Three blocks re-derived the
component's own rules inline in the test file and then asserted its own re-derivation:

- risk-class grant matrix (old lines ~96–131): the test recomputed
  `const allowSession = req.risk === "write" || req.risk === "safe"` and asserted on *that*
  local, never on the dialog. Deleting `allowSession`/`allowAlways` from the component would not
  have failed a single test.
- queue management (old lines ~133–189): built a plain array, called `.shift()` on it, and
  asserted the array shifted.
- double-submit guard (old lines ~228–253): defined a fresh local `answer()` function inside the
  test and asserted that *that* function guarded — the component's `resolving` flag was never
  loaded.

Plus the "resolveToolApproval" tests only asserted `=== true`, which is the hard-coded
browser-mode return value of the stub, not backend behavior.

**All of that re-derived logic is deleted.** Nothing was kept "for reference".

## What the file does now

`src/tests/approval.test.ts` mounts the real `src/lib/components/ApprovalDialog.svelte` via
`@testing-library/svelte` and asserts on rendered DOM + the actual IPC payload.

The seam is one level deeper than the packet asked for, and deliberately so: instead of stubbing
`$lib/api/tauri`, the tests mock `@tauri-apps/api/core`'s `invoke` and `@tauri-apps/api/event`'s
`listen` and set `window.__TAURI_INTERNALS__ = {}`. That makes `$lib/api/tauri` run its **real
Tauri branch**, so the tests also pin the wire contract the Rust side deserializes —
`invoke("resolve_tool_approval", { args: { id, decision, scope, target, pattern } })`. A regression
in the `args` wrapper (the documented Tauri v2 footgun in `tauri.ts`) now fails a test.

32 tests in 7 describe blocks:

| Block | Covers |
|---|---|
| rendering | nothing rendered before a request; event subscribed on mount; tool name + exact command shown; command rendered as text not markup (XSS); `role=dialog` / `aria-modal` / heading; backend prompt shown |
| risk presentation | badge label per risk class; **dangerous carries the red/destructive treatment**; unknown risk class falls back to "Unknown" *and* unlocks no standing grants (fail-closed); egress destination surfaced for external; destination line absent otherwise |
| offered grants by risk class | asserts the actual rendered button list — dangerous → `[Deny, Allow once]`, external → `[Deny, Allow once]`, write → `[Deny, Always allow, Allow for this session, Allow once]`, safe → `[Deny, Allow for this session, Allow once]` |
| decisions | each button's real IPC payload (once/deny/session/always); Escape → deny; Escape with no pending request sends nothing; dialog dismisses on delivery, on a stale `false` result, and on a thrown IPC error |
| double-submit guard | two synchronous clicks with the IPC promise held open produce exactly one `resolve_tool_approval`; buttons are `disabled` while in flight |
| request queue | head shown + "2 more waiting"; FIFO advance answers each request with its own id and re-renders the next request's *own* button set; a request arriving mid-decision is not lost |

### Mutation testing — proof the tests are not vacuous

Because the whole finding is "these tests pass no matter what the component does", I verified the
replacements by temporarily mutating `ApprovalDialog.svelte`, running the suite, and then
restoring the file byte-for-byte (`git diff --stat` afterwards shows **only**
`src/tests/approval.test.ts` modified — the component is untouched in this commit).

Round 1 — `allowAlways = $derived(true)`, drop the `resolving` guard, Escape approves instead of
denies:

```
Tests  7 failed | 25 passed (32)
 × falls back to Unknown for a risk class this frontend does not know
 × dangerous offers only Deny and Allow once
 × external offers only Deny and Allow once
 × safe offers a session grant but never a persisted always grant
 × Escape denies the shown request (safe default)
 × a double click resolves the request exactly once
 × advances FIFO, answering each request with its own id
```

Round 2 — hide the egress destination, silently widen the session button to `always`, strip the
red treatment off the dangerous badge, make `advance()` clear the whole queue:

```
Tests  4 failed | 28 passed (32)
 × presents a dangerous action with the destructive (red) treatment
 × surfaces the egress destination for an external request
 × Allow for this session grants the whole tool for the session
 × advances FIFO, answering each request with its own id
```

Every mutation was caught. The old test file would have passed all nine of those mutations.
