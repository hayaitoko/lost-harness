## What the Codex REJECT was about, and what changed

Codex: *"Placeholder public key, absent manifest, and silent fallback preserve
mutable `main` trust."* All three were true of `4605ec8`:

```rust
// 4605ec8, hf_search.rs:752 — the fail-OPEN line
let manifest = ModelManifest::load::<&Path>(&Path::new("model_manifest.json")).unwrap_or(None);
…
None => { let publisher = publisher_of(model_id); ("main", provenance_of(publisher)) }
```

Every verification failure (bad signature, malformed JSON, unreadable file) was
collapsed to `None`, and `None` then fell through to the **publisher allowlist**,
so an absent or forged manifest still produced a `Curated` label resolved against
the mutable `main` tip. The path was also dead on arrival: it read
`"model_manifest.json"` relative to the process cwd while `MANIFEST_FILENAME`
said `"model-manifest.json"`, and the public key was a base64-invalid
`PLACEHOLDER_…` string.

### 1. Fail-closed resolution (the load-bearing requirement)

- `resolve_manifest(storage_base, model_id) -> ManifestResolution`, whose state is
  one of `Verified { revision }` / `NotListed` / `Absent` / `Invalid { reason }`.
- `Provenance::Curated` is now produced in **exactly one place**:
  `ManifestResolution::provenance()`, and only when `Verified`. Grepping for
  `Provenance::Curated` in non-test code returns that single site plus the
  `parse_search_results` manifest-membership check.
- The publisher allowlist can no longer produce a trust label at all.
  `provenance_of(&str) -> Provenance` is **deleted**, replaced by
  `is_curated_publisher(&str) -> bool`, exposed as the explicitly-not-a-trust-signal
  `curated_publisher` flag. `staff_picks` filters on that flag, so the Staff-picks
  discovery list still populates without a manifest — the rows just say
  `community`, which is the truth.
- No silent degradation: `HfModelDetail.manifest` carries the `ManifestState`
  (including the `Invalid` reason string) to the renderer.
- A verified entry is authoritative in **both** directions: `apply_manifest_entry`
  replaces the host-reported digest AND drops any file the manifest does not
  list, so a `Curated` model can never offer a download whose expected hash came
  from the host serving the bytes.
- Revision handling is validated before URL construction. `parse_tree` and
  `list_quants` accept only `UNPINNED_REVISION` (`"main"`) or an immutable 40-hex
  commit sha; a manifest entry that pins `main`, a short sha, or a non-hex ref is
  rejected at load. (`4605ec8` spliced an unvalidated `revision` straight into
  `resolve_url` — an injection hole this closes.)
- The manifest path bug is fixed: resolution takes the app storage base and joins
  `MANIFEST_FILENAME`, so it reads `<storage base>/model-manifest.json`, not a
  cwd-relative file that never existed.

### 2. Signature scope + anti-rollback

- `4605ec8` signed `serde_json::to_string(&self.models)` only, so `version` and
  `signed_at` were unauthenticated. New payload is domain-separated and frames
  the header into the signed bytes:
  ```text
  lost-harness/model-manifest/v1\nversion=<u32>\nserial=<u64>\nsigned_at=<iso>\n<canonical models json>
  ```
  A valid signature therefore cannot be lifted onto a different serial or schema
  version. (`signed_at` is rejected if it contains a newline, so the framing is
  unambiguous.)
- New monotonic `serial: u64` field, separate from the schema `version`, plus a
  `<storage base>/model-manifest.serial` high-water mark written on every
  acceptance. A genuinely-signed but **older** manifest is refused as a replay
  (`ManifestError::Rollback`). Equal serial reloads fine; higher advances the mark.
- Whole-manifest validation after signature check: unknown schema version,
  malformed model id, empty file list, unsafe file path, non-sha256 digest, or a
  mutable/short revision rejects the entire manifest rather than half-trusting it.
- `ModelManifest` can only be obtained from `verify_manifest_json`, so an
  unverified manifest value cannot reach a trust decision by construction.

### 3. The placeholder key is gone

`MANIFEST_PUBLIC_KEY_B64` is now `Option<&str> = None`. No fake key, no
"development-only key" wording. `None` ⇒ `ManifestError::NoKeyConfigured` ⇒
nothing is ever `Curated`. I did **not** invent a production key.

## NEEDS-LUKAS — production manifest key ceremony (human-only)

This is the one gap I did not close, on purpose: generating or committing a
production key is not an agent's job. The full instructions are also in the doc
comment on `MANIFEST_PUBLIC_KEY_B64` in `hf_search.rs` so they cannot drift away
from the code.

**Until you do this, the app is fail-closed:** no model is ever labelled
`curated`, nothing is revision-pinned, and every download requires the explicit
community acknowledgement. Functionally safe, but there is also no supply-chain
protection beyond the host's own hash — so this should not be treated as
optional for a release.

1. **Generate the keypair on an offline machine.**
   ```bash
   openssl genpkey -algorithm ed25519 -out lh-manifest-private.pem
   chmod 600 lh-manifest-private.pem
   ```
   The private key never leaves that machine and is never committed. Store it
   encrypted (offline volume / password-manager attachment) with a written
   recovery plan. Losing it means a key rotation; leaking it means an attacker
   can mint `Curated` labels for arbitrary bytes.

2. **Extract the public half as RAW 32 bytes in base64** (openssl emits a 44-byte
   DER SPKI whose last 32 bytes are the key — the `tail -c 32` is required):
   ```bash
   openssl pkey -in lh-manifest-private.pem -pubout -outform DER | tail -c 32 | base64
   ```

3. **Embed the public key** in `src-tauri/src/models/hf_search.rs`:
   ```rust
   const MANIFEST_PUBLIC_KEY_B64: Option<&str> = Some("<that base64 string>");
   ```
   Commit only the public half.

4. **Write the manifest** at `<storage base>/model-manifest.json`
   (`~/Documents/Lost-Harness/model-manifest.json` in dev). Pick the models and
   look up each one's real commit sha and per-file sha256 (the HF tree endpoint
   `GET /api/models/{id}/tree/{sha}` reports `lfs.oid`; ideally confirm against
   bytes you downloaded and hashed yourself, since the point of the manifest is
   to stop trusting that endpoint):
   ```json
   {
     "version": 1,
     "serial": 1,
     "signed_at": "2026-07-29T00:00:00Z",
     "signature": "",
     "models": {
       "Qwen/Qwen3-0.6B-GGUF": {
         "revision": "<40-hex commit sha, NOT main>",
         "files": { "Qwen3-0.6B-Q8_0.gguf": "<64-hex sha256>" }
       }
     }
   }
   ```

5. **Emit the exact bytes to sign** — do not hand-canonicalise the JSON; the
   signed payload is domain-separated and framed:
   ```bash
   cd src-tauri
   LHP_MANIFEST_IN=/path/to/model-manifest.json \
   LHP_MANIFEST_PAYLOAD_OUT=/tmp/manifest-payload.bin \
     cargo test --lib models::hf_search::tests::emit_manifest_signing_payload \
     -- --ignored --nocapture
   ```
   This also validates the manifest content and tells you what to fix *before*
   signing (bad revision, bad digest, unsafe path).

6. **Sign and paste the hex** into the manifest's `signature` field:
   ```bash
   openssl pkeyutl -sign -inkey lh-manifest-private.pem -rawin \
     -in /tmp/manifest-payload.bin | xxd -p | tr -d '\n'
   ```

7. **Verify** — the app should report
   `"manifest": {"state":"verified","revision":"…"}` and `provenance: "curated"`
   for a listed model. An `"invalid"` state prints the exact reason.

8. **Every re-sign must bump `serial`.** The installation records the highest
   serial it has accepted in `<storage base>/model-manifest.serial` and refuses
   anything lower, so an old manifest cannot be replayed to re-bless a revision
   you pulled.
