# P04 — Finding H-01 (HIGH): Provider API keys stored in WebView localStorage

## Files changed

- `src/lib/stores/providers.svelte.ts` — API key security fix

## Summary

Removed `apiKey: string` from the frontend `Provider` interface and replaced it with
`hasApiKey: boolean` (a non-secret flag). The actual API key never enters the renderer
process: it is sent to the OS keychain via a one-shot `set_provider_api_key(provider_id, api_key)`
IPC and immediately discarded from frontend state.

Changes:

- **`Provider` interface** — `apiKey: string` → `hasApiKey: boolean`. The secret never lives
  in the frontend model.
- **`ProviderInput` interface** (new) — input shape for `addProvider` that still carries
  `apiKey: string` from the Settings form, since the form must collect it before the IPC send.
- **`migrateProviders()`** (new) — on startup, strips any residual `apiKey` fields from
  localStorage data and sets `hasApiKey` based on whether the key was non-empty.
- **`loadFromStorage()`** — uses `migrateProviders` so old `lh.providers.v1` data is
  sanitised on first load.
- **`persistProviders()`** — explicitly cleanses each provider to known-safe fields
  (defense in depth: even though the type system now prevents `apiKey` from existing,
  the runtime is explicitly stripped).
- **`setProviderApiKey()`** (new) — one-shot IPC to `set_provider_api_key(provider_id, api_key)`.
  Guarded by `isTauri` check; no-op in browser fallback.
- **`hydrateProviders()`** — no longer merges/stores API keys from local state. Maps
  `has_api_key` from backend (or defaults to `false`; preserves from local state until P05
  adds it to `ProviderInfo`).
- **`addProvider()`** — changed signature from `Omit<Provider, …>` to `ProviderInput`.
  Sends `null` to `api.addProvider`/`api.updateProvider` (key never flows through the
  provider-creation IPC). Sends key to OS keychain via `setProviderApiKey` only when a
  non-blank key was provided. Returns `hasApiKey: boolean` in the `Provider` — the key
  is dropped from renderer memory.

## Validation

- `npm run check` — **0 errors, 0 warnings**
- No code path writes `apiKey` into localStorage
- Keys flow only through the one-shot `set_provider_api_key` IPC
- Old localStorage data (`lh.providers.v1`) with `apiKey` fields is migrated on first load
- The `ProviderInput` type preserves backward compatibility with the Settings.svelte caller
  (which still passes `apiKey: string` in the form object)

## Follow-ups

- **P05** must implement the `set_provider_api_key` Rust IPC command and add `has_api_key`
  to the `ProviderInfo` response so `hydrateProviders` can read the truth from the backend.
- Once P05 is complete, the comment "preserve hasApiKey from local until P05" in
  `hydrateProviders` can be cleaned up (use backend value directly).
- Update `Settings.svelte` to read `hasApiKey` (not the removed `apiKey`) from `Provider`
  objects — currently harmless since `startEditProvider` always sets `apiKey: ""` (doesn't
  read from Provider), but a future refactor should remove the stale field.
- `browserAddProvider` in `tauri.ts` already ignores the key param (`_apiKey: string | null`).
  The browser fallback intentionally keeps no key material.
