## Design decisions

### 1. Why `ConfirmRequired` instead of `Block`
The codebase already had this exact pattern at the audio boundary
(`AudioEgressDecision::ConfirmRequired` + `ApprovalLedger::take_once`). Adding a
third policy would have been a fork. The gate now speaks the same language, and
`PublicSendConfirmations` mirrors `take_once`'s atomic check-and-consume.

The grant is fingerprinted over the **exact text**
(`sha256("privacy_gate.public_send" ⊕ canonical {text})`), domain-separated from
tool-action fingerprints, so a tool approval can never be replayed as a
message-send confirmation and vice versa.

### 2. Expiry: single-use AND time-limited
`take()` removes the entry under the same lock that checks it (so two concurrent
identical sends cannot both consume one confirmation) and refuses an entry older
than the TTL (default 120 s; `grant()` also sweeps stale entries). A poisoned
mutex returns `false` — fail closed.

### 3. Item 6, the `HeuristicClassifier` empty-spans hole — **decision + why**
The first attempt gated on `classification.spans.iter().any(...)`. Per
`Classification::spans`' own doc, that vec is **empty by contract** for
`HeuristicClassifier` and the `EnsembleClassifier` stub — so the H-12 block was
vacuously false in exactly the fresh-install / no-models configuration the
finding is about.

**Decision: the floor is the RULES LAYER, not the active classifier.** `floor_hit`
calls `crate::classifier::rules::detect(text)` directly, which is a free function
independent of whichever `Classifier` is installed. It therefore fires identically
under the ensemble, the rules classifier, and the heuristic. This is also what
`AudioEgressGate::tts_egress` already does, so the two boundaries now agree.

Two deliberate consequences:
- `RuleCategory::Proprietary` (the "confidential" / "do not share" keyword cues)
  is **excluded** at the text boundary. Under an explicit `Public` binding,
  prompting on the mere word "confidential" would train the user to click through
  confirmations, which destroys the prompt's value. The stricter audio boundary
  keeps the cues. Tested: a classifier that screams `Private` about benign text
  does **not** manufacture a confirmation.
- The floor no longer depends on the classifier's label/confidence at all, so a
  classifier that is wrong in either direction cannot suppress it.

### 4. Degraded affects `Auto` only; `Public`/`Private` unchanged
`Private` already refuses cloud unconditionally. `Public` is an explicit user
opt-in and still gets the un-tunable floor. Degraded escalation is limited to
`Auto` + cloud (→ `RouteLocal`), where the gate would otherwise be trusting a
rules-only miss as evidence of cloud-safety. Degraded + **local** endpoint is
still `Allow` — fail-closed that bricks on-device use would just get switched off.

### 5. Tool path: `ConfirmRequired` → `Deny`, not `Ask`
`HookResult::Ask` would loop: the dispatcher's post-approval re-run records a
grant against the **tool's** fingerprint, not the gate's text fingerprint, so
`PrivacyFilterHook` would Ask again on every pass. `Deny` is fail-closed and
strictly safer than the pre-H-12 behaviour (silent allow). The one-send round
trip is a message-path affordance.

## Honest gaps / risks

1. **The frontend was NOT exercised in the running Tauri app.** The banner and the
   "Send it this once" flow typecheck and compile (svelte-check + vite build) but
   nobody clicked them. Specifically unverified:
   - the banner's `fixed inset-x-0 top-0 z-40` placement vs each screen's own top
     bar (I chose fixed because every screen roots at `h-screen`, so an in-flow
     strip would push the app past the viewport — but it may overlap chrome);
   - whether `border-blocked` / `bg-blocked-soft` render as intended in both themes.
2. **`ConfirmRequired` is not persisted.** Like the whole `ApprovalLedger`, the
   confirmation store is in-memory, so a restart mid-confirmation loses the grant
   and the user re-confirms. This matches `hooks/approval.rs`'s documented
   "no half-durability (Q3)" stance, so it is deliberate, not an oversight.
3. **`AppState` grew a field (`gate`).** Cheap (`PrivacyGate: Clone` is Arc bumps)
   and it is the same gate the loop holds, but it is a second handle to the same
   object — a future refactor that rebuilds one and not the other would silently
   desynchronise them. Guarded by
   `get_classifier_health_reports_the_gates_shared_degraded_flag`.
4. **Nothing consumes `ConfirmRequired` on the tool path.** It maps to `Deny`
   (see decision 5). If tool calls ever need the one-send affordance, that needs a
   text-fingerprint-aware ledger path, not an `Ask`.
5. **The banner is polled once, on mount.** The flag is set at boot and is one-way,
   so there is nothing to re-poll today — but if anything ever calls
   `mark_degraded` mid-session (nothing does), the banner would not appear until a
   reload. Left as-is rather than adding an event channel nobody emits on.
6. **`RulesClassifier` returning `confidence: 0.0` for a miss** is inherited from
   56609b6 (the first attempt). I did not revisit it; `floor_hit` does not read
   confidence, so H-12 no longer depends on it, but any other caller that treats
   confidence as a certainty signal would see the changed value.
