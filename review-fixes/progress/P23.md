## Correcting the brief's diagnosis

The campaign brief described a "726-vs-683 contradiction" in HANDOFF.md (lines 231 vs
351/62). Reading the file, that framing is not quite right, and fixing it as stated would
have destroyed useful history.

HANDOFF.md is a **dated changelog**. Its figures — 726, 685, 683, 675, 671, 564, 542, 478,
332 … — are each the honest gate count on that entry's own date. They do not contradict
each other any more than two dated git tags do.

The genuine defects were narrower, and worse:

1. **A stale claim presented as current.** The header block said `cargo test --lib` →
   **726 passing** with no date qualifier, so a reader took it as today's state. It was
   180 tests out of date.
2. **A verify block that disagreed with itself.** The "How to verify the whole thing is
   healthy" runbook told the reader to `expect: 564 passed`, while a second block ~120
   lines later said `# 683 tests`. Both were wrong, and they contradicted each other
   inside the same document's *operational instructions* — the one place a wrong number
   actively wastes someone's time, because they will think the tree is broken.
3. **Stale absolute paths.** That same runbook pointed at
   `/Users/hayai/Desktop/lost-harness-product/…`, which is not this checkout.
4. **BUILD-MANIFEST.md:30** claimed **542 tests**, GLOBAL **v7**, PROFILE **v10**.

## Changes

- **HANDOFF.md** — replaced the undated header claim with a **"Current state —
  authoritative (2026-07-30)"** block: a gate table plus an explicit statement that every

  block wins any disagreement. That resolves the contradiction without rewriting history.
- **HANDOFF.md** — both verify runbooks now say `expect: 906 passed, 0 failed, 1 ignored`,
  and use repo-relative paths.
- **docs/BUILD-MANIFEST.md:30** — 542 → **906 tests**, GLOBAL **v7 → v9** (P08's executable
  pin migration), PROFILE **v10 → v11**. Both schema numbers were stale too; they were read
