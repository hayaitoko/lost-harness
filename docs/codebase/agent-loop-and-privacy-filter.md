# Agent loop + privacy filter (message egress path)

- **Purpose** — Decide, per user message, whether text may leave the device to a cloud model endpoint (the §7 "TRM"/privacy gate), enforce that decision at the actual HTTP boundary, and drive the streaming chat turn (including the bounded in-conversation tool-calling loop) that follows. This is distinct from the *tool*-level gating chain (`hooks::HookChain` / `tools::dispatch::ToolDispatcher`), which reuses the same `Binding`/`is_cloud` signals but lives in `src-tauri/src/tools/` and `src-tauri/src/hooks/`.

- **Key types / traits / functions**
  - `Binding` — `gate.rs:32` — `Auto | Public | Private`, per-conversation user override.
  - `GateDecision` — `gate.rs:43` — `Allow | Block(String) | RouteLocal`.
  - `PrivacyGate::check(&self, binding: &Binding, text: &str, is_cloud_endpoint: bool) -> GateDecision` — `gate.rs:77`. Pure policy function — does **not** touch the network itself. `Public` bypasses the classifier entirely; `Private` blocks iff `is_cloud_endpoint`; `Auto` classifies `text` and only consults `is_cloud_endpoint` when the label is `Private`/`Uncertain` (both → `RouteLocal` if cloud, `Allow` if not). `Uncertain` is deliberately treated the same as `Private` ("when uncertain, route to private tree" — comment at `gate.rs:17-18`).
  - `PrivacyGate::log_decision` — `gate.rs:126` — `tracing::info!` only (target `lhp::classifier`), logs a **hash**, never plaintext. The actual DB row is written by `AgentLoop::log_trm_decision`, not by the gate itself.
  - `is_private_endpoint(base_url: &str) -> bool` — `egress.rs:24` — parses the URL, checks `localhost`/`::1`, a *validated* dotted-quad IPv4 (rejects `10.evil.com` — see comment `egress.rs:6-9`) against RFC1918 + `127.0.0.0/8` + Tailscale CGNAT `100.64.0.0/10`, then hostname suffixes `.local`/`.lan`/`.internal`/`.ts.net`. **Anything that fails to parse as a URL, or has no host, returns `false` (treated as public/cloud)** — fail-closed toward "must screen this".
  - `Provider::is_private()` — `provider.rs:80` — thin wrapper over `is_private_endpoint(&self.base_url)`. This — not `Provider::kind` — is the load-bearing signal the gate uses for cloud-vs-local; a `Custom` provider pointed at a LAN IP is treated as private even though its `kind` says `Custom`.
  - `AgentLoop` — `loop_mod.rs:112` — fields: `gate: PrivacyGate`, `model_manager: Arc<ModelManager>`, `storage: Arc<Storage>`, `tools: Arc<ToolDispatcher>`, `stream_lock: tokio::sync::Mutex<()>`.
  - `AgentLoop::process_message(content, conversation_id, binding, provider_id, model, profile, app: AppHandle) -> Result<String>` — `loop_mod.rs:156`. The only public entry point. Returns the final assistant text (or, for a `Block`, the block reason string — **not an `Err`**, see gotchas).
  - `AgentLoop::find_local_provider(&self) -> Option<Provider>` — `loop_mod.rs:244` — first provider where `is_local() && is_private()` both hold (catches a `Cloud`-kind provider someone pointed at `localhost`, or a `Local`-kind provider misconfigured to a public URL — both must be true).
  - `AgentLoop::stream_to_provider(...) -> Result<String>` — `loop_mod.rs:261` — does the actual work: persists the user message, builds `Vec<ChatMessage>` history (with a system-prompt tool catalog prepended if any tools exist), then runs the bounded tool loop (see Data flow).
  - `AgentLoop::log_trm_decision(profile, conversation_id, decision, message_hash) -> Result<()>` — `loop_mod.rs:437` — writes a `TrmLog` row to `profile_db` (spec §3 schema: `decision` is only `"public"`/`"private"` — `Block` and `RouteLocal` both collapse to `"private"`) and also calls `gate.log_decision` for the tracing layer.
  - `ModelStreamer` trait — `loop_mod.rs:75` — abstracts `ModelClient::stream_chat` so tests can inject canned SSE. Production impl at `loop_mod.rs:88` just delegates. **`AgentLoop::stream_to_provider` does not actually use `ModelStreamer` at all** — it calls `client.stream_chat` directly (`loop_mod.rs:344`), where `client: ModelClient` came from `model_manager.get_client()`. The trait exists purely for the test harness's own hand-rolled loop (see Tests).
  - `sha256_hex(bytes: &[u8]) -> String` — `loop_mod.rs:491` — hex sha256, used for the TRM log's `message_hash`.
  - `ToolDispatcher::run_turn(own_output, ctx, binding, is_cloud) -> Option<ChatMessage>` — `tools/dispatch.rs:264` — parses tool calls out of **only the model's own current-turn output** (never a prior turn or tool result — the "parse only your own output" rule), dispatches each through `dispatch()`, and returns a single `ChatMessage::user(...)` of feedback, or `None` if the turn made no tool calls (this ends the loop).
  - `ToolDispatcher::dispatch(call, ctx, binding, is_cloud) -> ToolOutcome` — `tools/dispatch.rs:114` — runs registry lookup → availability → the `HookChain` (`[PrivacyFilter, Sandbox, Permission, FirstUseConfirm]`, first "no" wins) → execution. Notably: if the privacy filter hook marks the call `RoutingRequirement::LocalRequired` and `is_cloud` is true, `dispatch` **denies** the call outright (`tools/dispatch.rs:~170`) rather than silently running it — this is a second, independent enforcement point beyond the message-level gate.

- **Data flow / how it fits**
  1. Frontend invokes the Tauri command `send_message` (`ipc/mod.rs:365`) → `AgentLoop::process_message`.
  2. `process_message` acquires `stream_lock` for the whole call (see Invariants).
  3. Resolve `Provider` via `model_manager.get_provider(&provider_id)`; compute `is_cloud = !is_private_endpoint(&provider.base_url)`.
  4. `gate.check(&binding, &content, is_cloud)` → `GateDecision`.
  5. Always log the decision to `trm_logs` (`log_trm_decision`), **before** branching — even `Allow` is logged, for the audit trail.
  6. Branch:
     - `Block(reason)` → emit `stream:error` (source `"gate"`) and **return `Ok(reason)`** — no exception, no message ever persisted or sent.
     - `RouteLocal` → `find_local_provider()`; if none registered, `Err(...)` (surfaces as an IPC error to the frontend, not a `stream:error` event); else re-derive `local_is_cloud` for that provider and call `stream_to_provider` with `routing_decision = "route_local"`.
     - `Allow` → `stream_to_provider` with `routing_decision = "allow"` and the original `provider`/`is_cloud`.
  7. `stream_to_provider`: persist the user `Message` row first (so the transcript is consistent even if the model call later fails), build chat history (system tool-catalog + prior conversation messages, remapping stored role `"tool"` → replayed role `"user"` because the fenced-tool dialect carries results as plain text, not the native OpenAI `tool` role), then run the **bounded tool loop**:
     - `for round in 0..=MAX_TOOL_ROUNDS` (`MAX_TOOL_ROUNDS = 6`, `loop_mod.rs:338`): open `client.stream_chat`, forward each `SseEvent::Delta` as a `stream:token` Tauri event, assemble the full text, persist it as an `assistant` `Message`.
     - On `SseEvent::Error`, emit `stream:error` (source `"model"`) and `bail!` — this **does** propagate as an `Err` out of `process_message` (unlike a gate `Block`).
     - If this was the last allowed round (`round == MAX_TOOL_ROUNDS`), stop without dispatching tools (avoids a final untested extra round).
     - Otherwise call `tools.run_turn(&assembled, &exec_ctx, binding, is_cloud)`. If it returns `Some(tool_feedback)`: persist a `"tool"`-role `Message`, push both the assistant turn and the tool feedback onto `history`, and loop again. If `None` (no tool calls parsed): break — this is the final answer.
  8. Return the last assembled assistant text.
  9. Back in `ipc::send_message`, the IPC layer re-queries storage for the most recent `assistant` message to get its id (does not receive it directly from `process_message`), and returns a `SendMessageResponse`.

- **Invariants (do NOT break)**
  - **`stream_lock` serializes the entire `process_message` call**, not just the network stream (`loop_mod.rs:170`, guard held for the method's full body). This means: only one message can be in flight per `AgentLoop` (i.e. per app instance — `AgentLoop` is constructed once in `lib.rs:103` and put in `AppState`) at a time, across *all* conversations/profiles. A second concurrent `send_message` call will block until the first fully completes (all tool rounds, all persistence), not just until the SSE stream ends. Do not narrow this lock's scope without checking for the "storage/model_manager races" reasoning in the doc comment at `loop_mod.rs:104-111` — it was scoped deliberately.
  - **The gate decision is always logged to `trm_logs`**, including `Allow` (`loop_mod.rs:182-186`, before the `match`). If you add a new decision path, make sure it still logs before branching.
  - **`is_private_endpoint` fails closed**: unparseable URL or missing host → `false` (i.e., treated as a cloud/public endpoint, so the gate screens it) — never assume an unparseable URL is safe (`egress.rs:22-28`).
  - **IPv4 private-range check requires a validated dotted-quad** (`egress.rs:44-48`) specifically so a hostname like `10.evil.com` is *not* misdetected as private and skip privacy screening. Don't "simplify" this to a substring/prefix check.
  - **`RouteLocal` must never silently become `Allow` on a cloud endpoint.** `find_local_provider` requires *both* `is_local()` and `is_private()` (`loop_mod.rs:248`) — if only one holds, the loop errors out (`Err("...no local provider is registered")`) rather than choosing a not-actually-private provider.
  - **Tool loop only parses the model's own current output** (`tools/dispatch.rs:14-17`, `run_turn` doc comment) — never re-parses a persisted/replayed tool result or a prior turn, so a poisoned tool output can't forge a new tool call on replay. Tool-returned data is `guard_wrap`ped and status-line substrings are `neutralize_untrusted`d before being fed back into history (`tools/dispatch.rs:297-306`).
  - **A tool call whose `RoutingRequirement` is `LocalRequired` is denied outright if the conversation is on a cloud endpoint** (`tools/dispatch.rs`, inside `dispatch`'s gating-chain success branch) — this is enforced independently of, and in addition to, the message-level `PrivacyGate`. Don't assume the message-level gate is the only enforcement point for privacy-sensitive tool calls.
  - **TRM log never stores plaintext** — only `sha256_hex(content)` (`loop_mod.rs:185`, `TrmLog.message_hash`). Any future change that logs more context must keep this true (spec §3).
  - **The user message is persisted before the model is called** (`loop_mod.rs:280-298`, comment: "so the transcript is consistent even if the model call fails"). Don't reorder this after the streaming call.

- **Gotchas / watch-items**
  - **Production classifier is `RulesClassifier`, not `HeuristicClassifier` or `EnsembleClassifier`.** `lib.rs:73-74` wires `RulesClassifier::new()`. Both `gate.rs`'s and `loop_mod.rs`'s module doc-comments still describe the classifier generically as "trained model, or heuristic fallback" — that's stale relative to what's actually wired (as of this read, `RulesClassifier`, a deterministic regex/PII layer-0 detector, not the trained ONNX ensemble). `EnsembleClassifier` (`classifier/engine.rs`) is a real stub: `load()` always errors, `classify()` always returns `Uncertain`/0.0 — it is not connected to `ort`/ONNX yet despite the classifier bundle having been delivered (per project memory, 7/9). If you're asked to "wire the classifier," this is the seam (`EnsembleClassifier::load`, `classifier/engine.rs:44-49`), and `lib.rs`'s classifier construction is where the swap happens.
  - **`loop_tests.rs` does not test the real `AgentLoop`.** It defines a parallel `TestLoop<R>` struct (`loop_tests.rs:101-onward`) that **reimplements** a simplified version of `process_message`'s body (gate check → persist user msg → stream once → persist assistant msg), using a hand-rolled `TestStreamer` trait instead of `ModelStreamer`, and using `HeuristicClassifier` instead of production's `RulesClassifier`. Concretely this means: the bounded tool loop (`MAX_TOOL_ROUNDS`, `ToolDispatcher::run_turn` integration), `find_local_provider`'s actual routing (the `RouteLocal` test only asserts on the *logged decision*, not that a different provider was actually used — see comment `loop_tests.rs:428`), and `stream_lock` concurrency are **not exercised by any test** as of this read. A change to the real tool-loop-in-`stream_to_provider` code can silently break with all tests green. If asked to add coverage for the tool loop or concurrency, it needs new tests against the real `AgentLoop`, not `TestLoop`.
  - **`GateDecision::Block` is not an `Err`.** `process_message` returns `Ok(reason)` for a block (`loop_mod.rs:196`) — callers (and future refactors) must not assume `Result::Err` means "blocked"; only a model/stream error or an internal failure (missing provider, no local provider, storage failure) becomes `Err`.
  - **`ipc::send_message`'s `SendMessageResponse.routing_decision` is hardcoded to `"allow"`** (`ipc/mod.rs:~408`) regardless of what actually happened (`route_local`/blocked). The real per-message routing decision is only recoverable from the persisted `Message.routing_decision` field or the `trm_logs` table, not from this IPC response. If the frontend needs the true decision, this is a bug to fix, not to trust.
  - **`RulesClassifier` never returns `Uncertain` from its own layer-0 rules** (only `Private` or falls through to the soft-detector stopgap, which *can* return `Uncertain` — see `classifier/rules.rs:465+`) — so in the current wiring, "Uncertain" in practice comes only from the borrowed `heuristic::detect_health_info`/`detect_home_address` stopgap or from the still-stubbed `EnsembleClassifier`.
  - **Confidence for `RouteLocal` in the TRM log is a hardcoded `0.8`**, not the classifier's actual confidence (`loop_mod.rs:461-464`, comment explains the real confidence only reaches the tracing layer via `gate.log_decision`, not the DB row).
  - **`Provider::is_local()` (kind) and `Provider::is_private()` (URL-based) are different axes** — `is_cloud` passed around the loop is always `!is_private_endpoint(base_url)`, i.e., URL-based, **not** derived from `provider.kind`. A `Cloud`-kind provider pointed at `127.0.0.1` is treated as non-cloud by the gate.
  - Tool-role messages are persisted as role `"tool"` but replayed to the model as role `"user"` (`loop_mod.rs:316-320`) because the fenced-tool dialect doesn't use the native OpenAI `tool` role / `tool_call_id`. If you ever add a provider that expects native tool-call format, this remapping is the place to change, and it needs to stay in sync with `tools::calling`'s fenced-dialect parser.
  - `stream_to_provider` takes 9 positional args and is `#[allow(clippy::too_many_arguments)]` (`loop_mod.rs:260`) — easy to transpose `binding`/`routing_decision`/`is_cloud` when adding a call site; there's no builder.

- **How to extend**
  - **New binding type or gate rule**: edit `Binding`/`GateDecision`/`PrivacyGate::check` in `gate.rs`; add cases to `gate_tests.rs`. Remember `log_trm_decision`'s `Allow`/`Block`/`RouteLocal` → `"public"`/`"private"` mapping in `loop_mod.rs:452-455` if you add a new `GateDecision` variant — it's a hard `match`, will fail to compile and force you to handle it.
  - **New private-network range or hostname suffix**: edit `is_private_endpoint` in `egress.rs`; it's a pure function, easy to unit test directly (see the range/suffix test blocks referenced in `gate_tests.rs`'s doc comment). Keep the "validated dotted-quad" IPv4 guard intact.
  - **Wiring the real trained classifier**: implement `EnsembleClassifier::load`/`classify` for real in `classifier/engine.rs` (loading `ort` sessions, tokenizers, running layer-0 rules first per the doc comment at `engine.rs:56-64`), then swap the `Arc::new(RulesClassifier::new())` in `lib.rs:74` for `Arc::new(EnsembleClassifier::load(...)?)` with a fallback to `RulesClassifier`/`HeuristicClassifier` on load failure (the doc comments already describe this fallback contract).
  - **Changing the tool-round budget**: `MAX_TOOL_ROUNDS` is a local `const` inside `stream_to_provider` (`loop_mod.rs:338`) — not configurable today. To make it configurable, thread it through `AgentLoop::new` or `process_message`'s args.
  - **Adding a new event type the frontend should see mid-stream**: add a payload struct near `StreamTokenPayload`/`StreamErrorPayload` (`loop_mod.rs:53-67`) and an `app.emit(...)` call; the frontend's `stream:token`/`stream:error` listeners are in `src/lib/api/tauri.ts` (not reviewed here — check there for the JS-side contract before renaming an event).
  - **Changing what gets persisted per turn**: `Message` construction is inlined three times in `stream_to_provider` (user, assistant, tool) — keep `routing_decision` stamped consistently on all three if you touch this.
