## Summary

Three fixes applied to the MCP Streamable HTTP transport:

### H-02 — Redirect exfiltration of session headers

**Problem:** The reqwest client was built with default redirect policy, meaning HTTP
redirects were followed automatically. A redirecting MCP server could redirect a
JSON-RPC POST to a cross-origin destination, carrying the `Mcp-Session-Id` header
(and request args) along with it — enabling session token exfiltration.

**Fix:**
- Disabled automatic redirects via `.redirect(reqwest::redirect::Policy::none())` on
  the client builder.
- Implemented manual redirect following in the `post()` method with per-hop security
  gates:
  - Max 5 hop limit (`MAX_REDIRECT_HOPS`).
  - Every hop re-runs `validate_endpoint()` on the target URL.
  - Scheme downgrade (HTTPS → HTTP) is rejected.
  - Destination is DNS-resolved (for domain names) and checked against private,
    loopback, and unspecified address ranges via `is_private_destination()`.
  - The `Mcp-Session-Id` header is sent only on hop 0 — never forwarded across a
    redirect boundary.
- Added `is_private_destination()` helper: checks `Ipv4Addr::{is_private,
  is_loopback, is_unspecified}`, `Ipv6Addr::{is_loopback, is_unspecified,
  is_unique_local}`, or for domain names resolves via
  `tokio::net::lookup_host()` and inspects every returned address.

### M-01 — Unbounded body buffering before size check

**Problem:** The 4 MB response limit was checked *after* calling
`.bytes().await`, which buffers the entire response body before the cap is
enforced. A server sending >4 MB still triggers a full buffer before the error.

**Fix:**
- Replaced `.bytes().await` with streaming via `response.chunk().await` in a loop.
- A byte counter (`body.len()`) is checked *before* extending, using
  `saturating_add` to prevent overflow. Caps streaming at 4 MB without ever
  buffering more than the limit.

### L-04 — IPv6 loopback parsed as string, rejected

**Problem:** The loopback check used string matching (`matches!(host, "127.0.0.1" |
"::1" | "localhost")`). While `::1` matched the canonical form, expanded IPv6
representations like `[0:0:0:0:0:0:0:1]` were rejected. Also did not handle
case-insensitive "LOCALHOST" or trailing-dot "localhost.".

**Fix:**
- Changed to use `url.host()` match on `url::Host::Ipv4(addr)` /
  `url::Host::Ipv6(addr)` / `url::Host::Domain(d)` with standard library
  `is_loopback()`.
- Added `eq_ignore_ascii_case` for domain variants, including trailing dot.
- Added tests: `[::1]`, `[0:0:0:0:0:0:0:1]`, `LOCALHOST` (case-insensitive),
  `localhosT.` (trailing dot).
