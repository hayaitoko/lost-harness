## Summary

Added a Vitest-based frontend test harness covering the six security-sensitive flows identified in M-19:

1. **Provider mutation** — Tests the full CRUD lifecycle including the apiKey retention rule (blank = keep stored key, new key = overwrite), localStorage persistence round-trip, model cache, and the hydration merge path between browser-fallback and remote provider lists.

2. **Profile-switch races** — Tests rejection of unknown profiles, no-op on already-active, rapid sequential switches, persistence fallback, and conversation-clearing before rehydration.

3. **Approval-dialog nonces** — Tests the nonce (id) uniqueness requirement, the risk-class grant matrix (dangerous/external → once only, write → once+session+always, safe → once+session), queue FIFO ordering, Esc→deny contract, and the resolving flag guard against double-submit.

4. **Privacy routing/binding** — Component tests for BindingControl (3 radio buttons, aria-checked, onchange), RoutingBadge (route labels, button/span modes, custom labels), RouteDot (all 4 route states), and PrivacyEventBar (kept/stop variants).

5. **Downloads** — Tests the IPC contract that downloadModel throws in browser fallback (requires Tauri shell), the community acknowledgement parameter, and the contract that the backend never trusts a renderer-supplied URL.

6. **OAuth reconnect** — Tests the Gmail OAuth flow's IPC contracts (setGmailClient, gmailBeginConnect, gmailFinishConnect, gmailDisconnect all throw in browser fallback), per-profile isolation, needs_reconnect as a normal state, and client id format validation.
