## Findings
- **M-16** (MEDIUM): `security.csp` in `tauri.conf.json` was `null`, allowing any resource to be loaded by the webview. This is a CSP bypass risk — an attacker who places a malicious file in the app's resource directory or exploits a DOM-based XSS can load external scripts, exfiltrate data, or perform arbitrary network requests from the app's origin.

## Updated via
`2026-07-28T13:28:00Z`

## Files changed
- `src-tauri/tauri.conf.json` — only `security.csp` field edited (line 26)

## Fix applied
Set `security.csp` from `null` to:

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'
```

Policy rationale:
- **`default-src 'self'`** — restricts all resource types to the app's own origin. Blocks external images, frames, fonts, media, and objects.
- **`script-src 'self'`** — allows only bundled JavaScript. No inline scripts, no `eval()`, no external scripts. All frontend code is compiled by Vite into a single bundle (`/assets/app-*.js`).
- **`style-src 'self' 'unsafe-inline'`** — allows bundled CSS AND inline styles. The `'unsafe-inline'` is required because Svelte components use dynamic inline styles extensively (e.g. `style="grid-template-columns:…"`, `style="background:…"`, `style="--accent:…"`). Without this, the app would white-screen because many components' layout styles are computed dynamically at runtime.

**Not needed:**
- No `connect-src` exceptions — the frontend communicates with the Rust backend exclusively via Tauri IPC (`window.__TAURI_INTERNALS__`), which does not rely on CSP `connect-src`. All provider/MCP HTTP calls are made from the Rust backend via `reqwest`, not from the frontend.
- No `img-src` exceptions — all images are bundled in `dist/`.
- No `font-src` exceptions — using system fonts only.
- No `tauri://localhost` — Tauri 2 IPC is internal to the webview and doesn't require CSP entries.
