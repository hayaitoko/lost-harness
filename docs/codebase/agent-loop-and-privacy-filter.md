# Agent loop + privacy filter (message egress path)

- **Purpose** — `AgentLoop` (`src-tauri/src/agent/loop_mod.rs`) is the orchestrator for one user message: it decides whether the message may leave the device (the §7 "TRM"/privacy gate), enforces that decision at the model-call boundary, drives the streaming chat turn and its bounded in-conversation tool loop, assembles a cache-shaped prompt (curated memory summary + relevance snippets + deterministic compaction), and fires the background write-triggers (memory flush, skill reflection) that piggyback on a send. It also hosts the pieces that reuse the same loop off the main send path: one-shot delegated sub-agents (`run_subagent`), unattended cron turns (`run_cron`), the background queue runner that executes both (`agent::work_runner`), and the boot-time crash-recovery pass (`agent::crash_recovery`). This is distinct from the *tool*-level gating chain (`hooks::HookChain` / `tools::dispatch::ToolDispatcher`), which reuses the same `Binding`/`is_cloud`/classifier signals but lives in `src-tauri/src/tools/` and `src-tauri/src/hooks/`.

- **Data flow / how it fits**

  **1. The message send.** Frontend invokes `send_message` (`ipc/mod.rs:430`) → builds a `TauriResultSink` from the injected `AppHandle` → `AgentLoop::process_message`. `process_message` acquires `stream_lock` for the whole call (`loop_mod.rs:305`), resolves the `Provider` and `is_cloud = !is_private_endpoint(&provider.base_url)` (`loop_mod.rs:308-312`), loads the profile's `ClassifierConfig` (`loop_mod.rs:319-323`, defaults on any read error — a settings read must never block a send), then calls `gate.check_detailed(&binding, &content, is_cloud, &classifier_cfg)` (`loop_mod.rs:324-326`). The decision is **always** logged to `trm_logs` before branching (`loop_mod.rs:331-332`), including `Allow`.

  - `Block(reason)` → `sink.error(...)` and **`return Ok(reason)`** — no message is ever persisted or sent (`loop_mod.rs:335-338`).
  - `RouteLocal` (`loop_mod.rs:339-407`) — if the endpoint is cloud, first try **redact-and-send** (`plan_redaction`, `loop_mod.rs:348-380`): only fires if the profile's redaction toggle is on, the message has redactable spans, the redacted remainder re-classifies `Public`, **and** `conversation_is_cloud_safe` holds for the rest of the history — if all four hold, the turn streams to the *original* cloud provider with `routing_decision = "redact_send"`. Otherwise, find a local provider (`is_local() && is_private()`) or error out (`loop_mod.rs:383-406`).
  - `Allow` (`loop_mod.rs:408-468`) — **the whole-history cloud-safe guard**: if the endpoint is cloud, `conversation_is_cloud_safe` must hold for every already-persisted turn before this message can also go to cloud (`loop_mod.rs:420-452`). If it doesn't and no local provider exists, the send fails closed with a user-facing explanation (`loop_mod.rs:428-434`); if a local provider exists, the turn silently continues there instead (`routing_decision = "route_local"`). Only when the guard passes (or the endpoint isn't cloud) does the turn stream to the originally-resolved provider (`loop_mod.rs:453-467`).

  **The cloud-safe guard itself** (`conversation_is_cloud_safe`, `loop_mod.rs:710-777`): loads every persisted message in the conversation and requires each to classify `Allow` under `cfg` on a (simulated) cloud endpoint — **re-checking content**, not the persisted `routing_decision` (a message that was fine on a *local* endpoint may still be unsafe to replay to cloud; a test at `loop_tests.rs:790-823` locks this in). Results are cached per conversation in `cloud_safe_cache` (`loop_mod.rs:167`): once a conversation is found unsafe it stays unsafe (history is append-only, so that verdict can only get worse, never better); while still safe, only the messages added since the last check are re-scanned incrementally, so an ordinary long cloud chat is never re-scanned in full. A `ClassifierConfig` change invalidates the cached entry (tightening strictness can't ride a stale "safe" verdict). A **cold** scan (no cache entry yet — e.g. right after restart) is capped at 200 messages (`COLD_SCAN_CAP`, `loop_mod.rs:723`) and fails closed (stays local) beyond that, to bound the cost of a single huge conversation's first check.

  **2. `stream_to_provider`** (`loop_mod.rs:1148-1601`) — persists the user `Message` row first (`loop_mod.rs:1181-1199`, so the transcript is consistent even if the model call later fails), then assembles the model-facing history in three tiers (`loop_mod.rs:1201-1289`):
  - Tier 0 (stable prefix): the tool catalog, if any tools exist (`loop_mod.rs:1216-1220`).
  - Tier 1 (stable prefix): the always-loaded curated memory summary, wrapped with `guard_wrap_stable` seeded by the conversation id (`loop_mod.rs:1221-1229`, `assemble_curated_summary` at `loop_mod.rs:857-892`) — deterministic and byte-identical turn-over-turn so it's a reusable KV/prompt-cache prefix. The candidate fact set itself is frozen at the conversation's first turn (`frozen_summary_facts`, `loop_mod.rs:826-848`, a bounded cache) so a mid-conversation `remember` doesn't churn the prefix; the per-turn endpoint filter (private-local facts dropped on a cloud turn) is still applied fresh every turn, so the privacy wall holds even though the candidate set is frozen.
  - The trimmable middle: every prior persisted message except the current turn (`loop_mod.rs:1230-1258`). A `role: "tool"` row replays as `"user"` (the fenced dialect carries tool results as plain text, not the native `tool` role). A row with `routing_decision == "delegated"` (a `run_subagent`/work-runner result posted back into this conversation) is **guard-wrapped as untrusted `user` input on re-entry into the model context** even though the persisted/displayed copy stays clean plain text (`loop_mod.rs:1240-1253`) — a delegated helper can fetch the web, so its output must never replay as a trusted assistant turn.
  - Tail (volatile): the current turn. When redacting, the model sees `redaction.redacted_text`, never the original sensitive spans (`loop_mod.rs:1266-1269`); the per-message relevance snippets (`assemble_relevance_snippets`, `loop_mod.rs:899-955` — hybrid keyword+meaning-lane search, distance-gated, capped at 3, deduped against the summary) are prepended into this same user turn so there's never two consecutive user-role messages on the wire, and firing a recall emits the non-silent `memory:event("recalled", n)` (`loop_mod.rs:1276-1279`) — the sink's UI-facing acknowledgment that saved notes were used, never their content.
  - `pinned_from = history.len() - 1` (`loop_mod.rs:1285-1289`) marks the current turn's index — every round's compaction pass raises `keep_recent` to cover from here forward (`loop_mod.rs:1352-1356`), so the actual question can never be trimmed no matter how deep the tool loop runs.

  **3. The bounded tool loop** (`loop_mod.rs:1335-1598`, `MAX_TOOL_ROUNDS = 6` at `loop_mod.rs:1322`). Each round: `compact_history` shrinks the model-facing send (`loop_mod.rs:1357-1361`); any turns it drops (`compaction.trimmed`) are handed to `on_pre_compaction` for the memory flush (`loop_mod.rs:1362-1366`, see below) **before** they leave the wire; the round streams via `client.stream_chat_with_tools`, using the native `tool_calls` transport when `provider.supports_native_tools` and a tool spec exists, the fenced-dialect otherwise (`loop_mod.rs:1340,1367-1374`) — **never both parsed in the same round** (`loop_mod.rs:1525-1537`: native mode assembles `ToolCallFragment`s and calls `run_turn_native`; fenced mode calls `run_turn`, which parses only `own_output`, the type-enforced "model's own current-turn text" — `models::OwnOutput::from_stream_assembly`, minted once per round at `loop_mod.rs:1419`). The round persists its assistant turn (marking `aborted: true` iff this was the forced stop at `MAX_TOOL_ROUNDS`, `loop_mod.rs:1434,1456`) and books a usage-ledger row (`loop_mod.rs:1463-1502` — local/private is always `$0`, cloud cost is priced only when the endpoint reported token usage and the model is in the pricing table, otherwise recorded as `None`/"unknown", never guessed). `resolve_turn_outcome` (`loop_mod.rs:1539-1558`, free fn at `loop_mod.rs:1710`) drives any `NeedsLocalReroute` outcome: if a local provider is found, the rest of *this turn* switches to it (`is_cloud = false`, `routing_decision = "tool_reroute_local"`) and fires the ephemeral `stream:local_reroute` event with the detailed reason (never persisted — the persisted feedback is a reason-free banner, `reroute_banner`, `loop_mod.rs:1683-1688`); if none is found, the call is hard-denied and the rest of the batch continues on the same endpoint. Tool feedback is persisted with role `"tool"` and the loop repeats; no tool calls parsed ⇒ that round's text is the final answer.

  **4. Background write-triggers** — fired from inside `on_pre_compaction` (`loop_mod.rs:967-1017`) and `consolidate_on_new_chat` (`loop_mod.rs:1025-1091`). Both run cheap synchronous dedup/marking work *under* the stream lock, then `tauri::async_runtime::spawn` a single detached task. `on_pre_compaction` only ever runs the memory flush (`memory_flush::run_flush`). `consolidate_on_new_chat` — called when a new conversation is created — runs the memory flush's new-chat nudge (`run_new_chat_nudge`, sweeps the most-recently-updated *prior* conversation for facts the on-stream flush missed) **then, sequentially in the same task, not concurrently**, the skill-reflection new-chat trigger (`skill_reflect::run_new_chat_reflect`) if the (DB-backed, default-off) `skill_reflect_enabled` toggle is on (`loop_mod.rs:1075`, `storage/global.rs:1427-1436`) — sequential specifically because both would otherwise touch the shared, `!Sync` `global.db` connection concurrently (`loop_mod.rs:1028-1030`). Both extractors are local-model-only (`LocalModelExtractor`/`LocalModelDrafter` can only ever reach an `is_local() && is_private()` provider) and guard-wrap the excerpt before sending it to that local model, so a prompt-injection line in the trimmed turns can't hijack the extraction. A memory fact is re-classified and routed through the same sensitivity path as `remember`/`save_memory` (a secret is `NeverPersist`, dropped — never even written locally); a drafted skill is **always saved `Pending`** (`skill_reflect.rs:353`) — inert until a human approves it in Settings → Skills, never auto-searchable/loadable. `run_new_chat_reflect` additionally skips a walled profile entirely (`skill_reflect.rs:385-387`) so autonomous drafting can never leak a walled profile's content into the shared global skills table.

  **5. `run_subagent`** (`loop_mod.rs:504-577`) — Wave 4.3c's `delegate` tool execution (delegate itself only enqueues a `work_items` row — see `tools::delegate`'s module docs for why: `AgentLoop` owns the `ToolDispatcher` that owns `delegate`, so `delegate` holding an `Arc<AgentLoop>` back would be circular). Builds a **fresh** `AgentLoop` sharing the parent's `gate`/`model_manager`/`storage` but with `tools` restricted to `tools_allowlist` via `ToolDispatcher::restricted` (same full gating chain per call — no floor-cap, per Lukas's decision #3). Creates an ephemeral sub-conversation, leads the first (only) user turn with the persona's `system_prompt` (v1 simplification — not a true system-role override yet), calls `process_message` with a `HeadlessSink`, then **deletes the ephemeral sub-conversation** regardless of outcome (`loop_mod.rs:575`) — it's scratch space, never a first-class chat. The result is posted into the **parent** conversation by the caller (`work_runner::run_one_item`, not this method) as a message labeled `routing_decision = "delegated"`, which is what triggers the guard-wrap-on-re-entry behavior described in step 2 above. **This re-entry branch (`loop_mod.rs:1240-1253`) has no dedicated test** — flagged below.

  **6. `run_cron`** (`loop_mod.rs:586-648`) — Wave 4.4's unattended scheduled-job execution. Hardcoded `Binding::Private` and a `local && private` provider (`loop_mod.rs:592-597`, errors out if none exists) — an unattended job must never egress, no exceptions. Uses `ToolDispatcher::headless()` (no interactive approval prompt possible) and a `HeadlessSink`. Delivers into the job's `target_conv` if it still exists, or a fresh dedicated conversation otherwise.

  **7. `work_runner::spawn_work_runner`** (`work_runner.rs:48-112`) — the fire-and-forget background loop (spawned once at boot, `lib.rs:215-218`) that polls every profile every `POLL_INTERVAL` (2s), atomically claims due `work_items` (`ProfileDb::claim_next_due_work`, an atomic `UPDATE ... RETURNING`), and runs each claimed item under a shared `MAX_CONCURRENT_HELPERS = 4`-permit semaphore (acquired *before* spawning the task, so the drain loop itself backpressures). Each item runs inside an inner supervised task (`work_runner.rs:88-105`) so a panic inside `run_subagent`/`process_message` still terminalizes the work item (`WorkState::Failed`) instead of leaving it `running` forever. A helper run is capped at `HELPER_DEADLINE = 300s` (`work_runner.rs:43`); success, failure, *and* timeout all post a labeled message back into the target conversation (`work_runner.rs:185-236`) — the user is never left with "dispatched" then silence. `schedule_due_cron_jobs_at` (`work_runner.rs:250-276`) enqueues due-and-enabled cron jobs as `Cron` work items exactly once per matching minute (a `cron:<id>@<minute>` claim key plus a `last_run_at` guard); `run_cron_item` (`work_runner.rs:282-310`) executes one via `AgentLoop::run_cron` under the same deadline.

  **8. Crash recovery** (`crash_recovery.rs`, run once at boot, `lib.rs:69-76`, before anything else touches storage). `reconcile_profile_db` (`crash_recovery.rs:94-232`) scans every conversation's last message; only an `assistant` row that opened a tool fence, has no reply, **and is not already marked `aborted: true`** counts as crash damage (`crash_recovery.rs:166-180`) — a deliberate `MAX_TOOL_ROUNDS` stop (which the loop marks `aborted: true`, `loop_mod.rs:1434,1456`) is otherwise byte-identical to a real crash on disk, and `aborted` is the only thing that tells them apart (a genuine crash dies before that flag is ever written). A matching conversation gets a `role: "tool"` repair row (`REPAIR_CONTENT`, tagged `error: "interrupted_by_crash"`) so the next real turn sees a clean `user → assistant(tool call) → tool(interrupted) → …` state; idempotent by construction (a second boot pass sees the last message is now `"tool"`, not `"assistant"`, and skips). `run_boot_pass` (`crash_recovery.rs:237-287`) also calls `db.terminalize_orphaned_work` per profile — any `work_items` row a crash left `running` is failed rather than silently re-run (never re-run a mutating/dispatched action twice). There is a standing `TODO` at `crash_recovery.rs:217-220` to also write a `tool_audit` row once that table exists — not required for the repair to be durable/visible today, just deferred.

- **Invariants (do NOT break)**
  - **`stream_lock` serializes the entire `process_message` call** (`loop_mod.rs:305`, held for the method's full body, including all tool rounds and all persistence) — one message in flight per `AgentLoop` (one per app instance) at a time, across *all* conversations/profiles.
  - **The gate decision is always logged to `trm_logs`, including `Allow`**, before branching (`loop_mod.rs:331-332`).
  - **`is_private_endpoint` fails closed**: unparseable URL or missing host → `false` (treated as cloud, so the gate screens it) — `egress.rs:20-33`.
  - **The IPv4 private-range check requires a validated dotted-quad** (`egress.rs:44-48`) so `10.evil.com` isn't misdetected as private.
  - **`RouteLocal` must never silently become `Allow` on a cloud endpoint.** `find_local_provider` requires *both* `is_local()` and `is_private()` (`loop_mod.rs:1131-1136`) — if only one holds, the caller errors rather than picking a not-actually-private provider.
  - **The cloud-safe guard re-checks CONTENT, not the persisted `routing_decision`** (`loop_mod.rs:737-743`, locked in by `loop_tests.rs:790-823`) — a message that was `Allow`ed on a local endpoint is not automatically safe to replay to cloud.
  - **Redact-and-send only fires when the redacted remainder re-classifies clean AND the rest of the history is cloud-safe** (`loop_mod.rs:348-380`, `plan_redaction` at `loop_mod.rs:659-701`) — redaction alone is never trusted; the re-classify pass is the load-bearing check. Redaction placeholders carry a per-turn random nonce (`loop_mod.rs:680`) so untrusted tool/web content pulled into the conversation can't forge a `[REDACTED:…]` string that rehydration would blindly expand into a real value.
  - **The current turn is pinned through the tool loop.** `pinned_from` (`loop_mod.rs:1285-1289`) raises `keep_recent` every round (`loop_mod.rs:1352-1356`) so `compact_history` can never trim the actual question, however deep the tool loop goes.
  - **Tool loop only parses the model's own current output** — `OwnOutput::from_stream_assembly` (`loop_mod.rs:1419`) is the type-level enforcement; `ToolDispatcher::run_turn` parses only that (`tools/dispatch.rs:697-725`), never a replayed tool result or a prior turn.
  - **Native and fenced tool-call transports are mutually exclusive within one round** (`loop_mod.rs:1525-1537`) — a server that streams native `tool_calls` without `supports_native_tools` set is logged and ignored, never silently parsed as fenced.
  - **A tool call whose `RoutingRequirement` is `LocalRequired` is denied outright on a cloud endpoint** (`tools/dispatch.rs:505-519`), independent of the message-level gate — don't assume the message-level gate is the only privacy enforcement point for tool calls (see the classifier.md KNOWN GAP: this hook still gates at default thresholds, not the profile's).
  - **TRM log never stores plaintext** — only `sha256_hex(content)` (`loop_mod.rs:1817`, `TrmLog.message_hash`).
  - **The user message is persisted before the model is called** (`loop_mod.rs:1181-1199`) — don't reorder this after the streaming call.
  - **A delegated helper's result is guard-wrapped on re-entry into the model context, but stored clean.** (`loop_mod.rs:1240-1253`.) The user sees a plain answer; only the model-facing replay is neutralized.
  - **Memory-flush and skill-reflection extraction never egress to a cloud model** — both extractors can only ever reach an `is_local() && is_private()` provider (`memory_flush.rs:90-97`, `skill_reflect.rs:104-111`), and skip entirely (without marking anything swept) when none exists, so a later round or restart still catches the content.
  - **An autonomous skill draft is always saved `Pending`, never `Approved`** (`skill_reflect.rs:353`) — the whole safety model for Wave 4.2 rests on this one line.
  - **`run_cron` is hardcoded to `Binding::Private` and a `local && private` provider** (`loop_mod.rs:592-597`) — an unattended job must never have a path to cloud egress.
  - **Crash recovery only touches an `assistant` row with an open tool fence that is not already `aborted: true`** (`crash_recovery.rs:166-180`) — a deliberate `MAX_TOOL_ROUNDS` stop must never be "repaired" as if it were a crash.

Both the message-level gate and the tool-dispatch gating chain share the *same* `Arc<dyn Classifier>`, so they always classify identically. Older docs/comments in this codebase (including this file's prior revision) said the ensemble was an unwired stub — that is no longer true; see `classifier.md` for the full writeup, including the tokenizer-padding gotcha and the per-profile threshold config.
  - **`ipc::send_message`'s `routing_decision` bug is fixed.** It used to be hardcoded to `"allow"`; it now re-queries the persisted conversation for the most recent `assistant` row's real `routing_decision` via `latest_assistant_routing` (`ipc/mod.rs:413-422`), defaulting to `"allow"` only when that row carries no decision at all. If you're chasing a stale claim that this is still hardcoded (an older doc/README says so), it isn't — check `ipc/mod.rs:481-482` directly before trusting that claim again.

A change to how those wire together inside `process_message` itself can regress with every existing test green.
  - **`run_subagent`'s delegated-result re-entry has no dedicated test.** The guard-wrap-on-replay behavior at `loop_mod.rs:1240-1253` (stored clean, guard-wrapped only when fed back to the model) is exercised by inspection/design, not by an automated test as of this read — flagged for anyone touching that branch.
